Volant renders Jinja2 on the controller with [MiniJinja](https://github.com/mitsuhiko/minijinja) and adds Ansible's filters, tests and lookups on top.

## Strict by default

Templates render in strict mode. An undefined variable is an error, not an empty string, unless you guard it:

```yaml
- debug:
    msg: "{{ release | default('latest') }}"
  when: release is defined or use_latest | bool
```

A `when` whose value is not a boolean is rejected as well.

## Conditions

`when`, `changed_when`, `failed_when` and `until` take one expression or a list of them. With a list, every expression must hold.

```yaml
- command: /opt/app/migrate.sh
  register: migrate
  changed_when: "'applied' in migrate.stdout"
  failed_when:
    - migrate.rc != 0
    - "'already up to date' not in migrate.stderr"
```

A condition wrapped in `{{ }}` that renders to a string is evaluated once more as a condition, as ansible-core 2.19 does. With `healthy: "true"` in the play's `vars`, `when: "{{ healthy }}"` runs the task. This second evaluation never happens when the first render read a value from a managed host: the task fails with `Encountered untrusted template or expression.` instead. See [Trusted and untrusted values](/variables/trust/).

## What is available

On top of MiniJinja's own Jinja2 builtins, Volant adds these from Ansible:

| Kind | Names |
|---|---|
| Filters | `default` / `d`, `bool`, `int`, `float`, `mandatory`, `ternary`, `combine`, `dict2items`, `items2dict`, `to_json`, `to_nice_json`, `from_json`, `to_yaml`, `to_nice_yaml`, `from_yaml`, `basename`, `dirname`, `split`, `regex_replace`, `regex_search`, `regex_findall`, `regex_escape`, `b64encode`, `b64decode`, `comment`, `difference`, `intersect`, `union`, `flatten`, `to_uuid`, `type_debug`, `quote` |
| Tests | `truthy`, `falsy`, `match`, `search`, `regex`, `contains`, `changed` / `change`, `failed` / `failure`, `succeeded` / `success` / `successful`, `skipped` / `skip`, `version` (and `version_compare`) |
| Lookups | `env`, `file`, `vars`, `pipe`, `first_found`, `fileglob`, `template` |
| From `ansible.utils` | the `ansible.utils.ipwrap` filter, under that name only |

Every filter, test and lookup in this list also answers under its `ansible.builtin.*` name, so `{{ data | ansible.builtin.to_json }}` works. A filter, test or lookup that is not in this list runs in the controller's Python helper with ansible-core's own code, [when Python is available](/variables/python-helper/). That includes the plugins of other collections.

`first_found`, `fileglob` and `template` look for files along `ansible_search_path`. In a role's task that is the role's directory, the directory of the task's file, then the playbook's directory. Outside a role it is the playbook's directory. `role_path` is set in a role's task and is undefined outside one. `fileglob` tries a relative pattern under `files/` of each entry, then in the entry itself, and the first entry with a match wins. It returns files only, sorted, and a single match comes back as a string. Each one is checked against ansible-core in the golden test corpus under `crates/volant/tests/golden`.

## Python methods

A template can call the methods Python gives to its values, as it can in ansible-core. A method that Volant does not run fails with its own name, so nothing is skipped without a message.

These `str` methods run, with the arguments and keywords Python takes and Python's wording for a wrong call (`must be str or None, not int`, `substring not found`):

| Group | Methods |
|---|---|
| Cut and join | `split`, `rsplit`, `splitlines`, `partition`, `rpartition`, `join`, `expandtabs` |
| Trim and pad | `strip`, `lstrip`, `rstrip`, `removeprefix`, `removesuffix`, `center`, `ljust`, `rjust`, `zfill` |
| Search | `find`, `rfind`, `index`, `rindex`, `count`, `startswith`, `endswith`, `replace` |
| Case | `upper`, `lower`, `title`, `capitalize`, `swapcase`, `casefold` |
| Test | `isalpha`, `isalnum`, `isdigit`, `isdecimal`, `isnumeric`, `isspace`, `islower`, `isupper`, `istitle`, `isascii`, `isidentifier`, `isprintable` |
| Other | `format`, `format_map`, `translate`, `maketrans` |

Positions count characters, not bytes, and `start` and `end` take negative values. `split(maxsplit=1)` and the other keyword forms work. `startswith` and `endswith` take a text or a tuple of texts. A list is accepted as a tuple, because Volant's Jinja has no tuple type.

What differs from CPython:

- `casefold` is lower case plus `ß` to `ss`. It is not the full Unicode case folding.
- `isdigit`, `isalpha` and the other tests outside ASCII follow Rust's Unicode tables. `'½'.isdigit()` is true here and false in Python.
- A format field can read an item (`{0[a]}`, `{a[0]}`) but not an attribute (`{0.real}`).
- A width, a count or a precision that would make a method build more than 256 MiB of text (`'a'.ljust(10000000000)`, `'{:.300000000f}'.format(x)`) stops the task with an error that names the limit. Python builds the text until the machine runs out of memory. A number too large for an index gives Python's own error, `Python int too large to convert to C ssize_t`.
- `encode` and `decode` are not available, because Volant has no bytes values.
- A backslash escape such as `'\n'` inside a template string is read by the template engine. ansible-core 2.19 keeps the two characters. Pass a value in a variable when the text must hold a real newline.

### Lists and mappings

`list` and `dict` methods run too: `append`, `extend`, `insert`, `remove`, `pop`, `sort`, `reverse`, `index`, `count`, `copy` and `clear` on a list, and `get`, `keys`, `values`, `items`, `pop`, `popitem`, `setdefault`, `update`, `copy`, `clear` and `fromkeys` on a mapping. `keys()`, `values()` and `items()` give lists. `sort` takes `reverse`, and `key` only as `none`. The usual ways to write a change are `{% set _ = items.append(x) %}` and `{{ items.append(x) or '' }}`: the method changes the list and answers `none`.

A template changes a list or mapping in place, and other names for the same value see the change:

```jinja
{% set seen = [] %}
{% for host in groups['web'] %}{% set _ = seen.append(host) %}{% endfor %}
{% set alias = seen %}{% set _ = alias.append('db') %}
{{ seen }}   {# every web host, then db #}
```

This follows Python and ansible-core 2.19, which agree on these cases (each is a row of the golden corpus):

- A value read from a variable is a copy for the string being rendered. A play variable `x` that a template changes with `x.append(1)` is changed for that template only. The next task, the next field of the same task and the next template read it as it was. There is no change to a variable that outlasts the render.
- Inside one template, `b = a` names one list, and a change through `b` shows in `a`. `b = a | list` and `b = a.copy()` make a new list.
- A list or mapping inside another is reached by `x[0]`, `x.key` and `for item in x` as the same object, so `d.a.append(1)` changes `d`. A value stored by `append`, `extend`, `insert`, `update` or `setdefault` is a copy, and so are the values that `get`, `items`, `values` and `copy` answer.
- `d.setdefault('k', []).append(1)` changes `d`. `v = d.setdefault('k', [])` followed by `v.append(1)` changes `d` here, and does not in ansible-core.

What differs from ansible-core:

- A list or mapping that a template passes to a macro, `namespace()` or another call is the same object in Volant. ansible-core passes a copy, so a macro that changes its argument changes the caller's list only here.
- ansible-core 2.19 keeps the error of a call whose result is never read. `{% set _ = [1].remove(5) %}` is no error there. It is one here.
- A list that `a + b` or a slice `a[1:]` built cannot be changed: write `(a + b) | list`. The error says so.
- A list that a call has just built and that no variable holds, such as `(x | list).append(1)`, is changed as a copy: the call answers as Python does, and nothing else changes.
- A list that grows inside a `{% for %}` over itself is read up to its length at the start of the loop.
- `{% do %}` is accepted here and refused by ansible-core 2.19, which does not enable `jinja2.ext.do`. Use `{% set _ = ... %}` in a template that has to run on both.
- `items()` and `popitem()` give lists where Python gives tuples, so they print as `['a', 1]` and not `('a', 1)`.
- `sort(key=...)` with a function is not available.

`.get()`, `.keys()`, `.values()` and `.items()` on other mapping-like values, such as `hostvars` and the loop variable, come from `minijinja-contrib`'s Python compatibility layer.

`difference`, `intersect` and `union` build a Python `set` in ansible-core, whose order is its own: small integers happen to come out sorted, and strings come out in an order that changes with `PYTHONHASHSEED` from one run to the next. Volant sorts the result when every element is an integer, which matches every integer case measured, and otherwise keeps the order in which the elements first appeared. On strings, that order is not guaranteed to match a given run of ansible-core.

## Rendering a template file

The `template` module and `lookup('template')` share one render, and it differs from a task argument's render in one way: it renders the file's text **once**. A task argument goes through further passes, which is how a value that still holds `{{ ... }}` after rendering can be read as a template again. A template file does not get that second pass, so a value a managed host contributed lands in the written file as plain text and never runs as a template of its own.

Text that a `raw` block writes, or a string such as `'{{'`, is literal: it is not rendered again as an argument, in a variable, in a `set_fact` value or in a loop item. A variable that holds a `raw` block is read to its end first, so `a: "{{ b }}"` with `b: "{% raw %}{{ x }}{% endraw %}"` gives `{{ x }}`.

It takes the options the `template` module reads:

| Option | Default | Effect |
|---|---|---|
| `trim_blocks` | on | Remove the first newline after a block tag. |
| `lstrip_blocks` | off | Strip the whitespace before a block tag on its line. |
| `newline_sequence` | `\n` | Line endings of the written file: `\n`, `\r` or `\r\n`, escaped or literal. |

The file's own trailing newline survives the render. [Action plugins](/reference/action-plugins/#template) covers the rest of what the `template` module does.

## Not there yet

- A string that reads two variables, one of them chained through a third that holds a `raw` block, is rendered once more than in the reference.
- A value under `!unsafe` is data and is never templated. A `!vault` value is decrypted; see [Vault](/variables/vault/).
- The `inventory_hostnames` and `varnames` lookups are not supported yet.
- In a template file, `template_host`, `template_uid`, `template_run_date` and `template_mtime` are not set, unlike `template_path`, `template_fullpath` and `ansible_managed`.
- In a template file, `{% include %}` and `{% import %}` fail: nothing loads a second file during a render.
- The six delimiter options (`variable_start_string` and its five relatives) and an `output_encoding` other than UTF-8 are not supported yet.

## Performance on large inventories

Resolving variables costs more than linear time in the number of hosts. Two changes have removed most of that cost: every host reads one shared `hostvars` map, and inventory-wide values such as `groups` are built once per batch instead of once per host and task. Nothing in a playbook, an inventory or `ansible.cfg` changes this cost.
